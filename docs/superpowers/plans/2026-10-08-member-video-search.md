# 影音專區搜尋：下一階段

狀態：規劃，尚未實作。先完成本次影音列表與觀看頁改版，再獨立交付搜尋。

本次改版延續 Mac M4 的觀看頁與說明欄，列表依最新確認改為 cursor 批次捲動載入，取代原計畫的分頁。會員留言仍依既有 M6 計畫另階段交付。

## 操作與畫面

- 影音列表上方提供搜尋框。輸入後按 Enter 或搜尋按鈕送出；URL 使用 `/[locale]/member-videos?q=...`，可重新整理、分享並保留查詢。
- 第一階段搜尋影片標題與影片說明；不搜尋字幕或影片內容。不加入頻道、觀看次數、廣告、熱門排序或推薦演算法。
- 搜尋結果採 YouTube 的橫向列表：左側較大的 16:9 圓角縮圖，右側標題、上傳時間與最多兩行說明。手機改成縮圖在上、資訊在下。
- 結果沿用本次 LoadMoreTrigger，往下捲動逐批載入，載入失敗保留結果並提供重試。沒有結果時顯示查詢詞及清除搜尋的操作。
- 有符合查詢的直播時置頂，沿用紅色「直播中」chip；不符合查詢的直播不出現在結果。開播時間與上傳時間分開表達。
- 點選結果進入現有觀看頁；返回搜尋保留查詢、已載入深度與捲動位置。保留的是導覽狀態，重新進入仍需驗證權限及取得新資料。

## 資料與契約

- hhc-web-api 負責搜尋與可見性判斷；只回傳當下有權限、已發布、未到期且媒體可用的影片。沿用會員資格、影音 entitlement 與法律條款檢查。
- 對現有 member recordings 分批讀取加入可選 `q`，保留無 q 的行為。直播搜尋沿用相同查詢語義及現有 liveState。
- q 去除頭尾空白；空字串視為無搜尋，限制最多 100 個 Unicode 字元。第一階段為不分大小寫的字面包含比對，搜尋標題或說明；SQL 使用參數及轉義 `%`、`_`、反斜線，不將使用者輸入當成 wildcard。
- 命中結果按上傳時間 DESC、ID DESC 排序。cursor 必須綁定正規化查詢與排序版本；不同查詢不能重用同一 cursor。
- 查詢變更時取消舊請求、清空 cursor 與結果；防止較晚返回的舊查詢覆蓋目前結果。直播狀態更新維持去重，直播轉錄影後不重複顯示。
- 回應維持 private/no-store。縮圖沿用有權限檢查的 Blob URL 與元件期間記憶體暫存；不加入持久化私人縮圖快取。
- 搜尋資料量與查詢耗時有實測瓶頸時再評估索引；本階段不引入搜尋服務或全文搜尋引擎。
