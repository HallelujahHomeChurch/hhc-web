# 週報繁轉簡與收尾驗收設計（待審核）

## 目標與邊界

從已校對的繁中一般版結構化內容產生簡中線上草稿，不重讀簡中 PDF、不使用 LLM；沿用 Admin 校對與獨立發布。這不是英文翻譯、兒童版模板或簡中 PDF 產生器。維持既有閱讀授權，停在 merge 前。

## 已核對現況

- hhc-web-api 的 Document validation、Admin 儲存與擷取查詢有 general/zh-Hant 限制，不能只解除前端路由限制。
- Admin 已有 component 編輯、原稿/線上預覽、校對、三方比對與歷史版本，但未完成真實上傳到官網閱讀的整條驗收。
- 目前讀者 Demo 模擬會員及暫存資料，不代表後端或真機驗收。

## 使用流程

1. 上傳繁中 PDF，擷取後人工修正；完成繁中排版驗證與校對。
2. Admin 顯示「產生簡中草稿」。未儲存、排版未完成或未校對時不能執行。
3. 後端固定來源 revision，使用固定版本 OpenCC 與字形轉換設定，轉換 component 文字、標題/副標與固定模板文字；不改人名用詞或換成另一經文譯本。
4. 沿用 component/段落/句子結構，重新產生簡中排版與字型覆蓋檢查。不能複製繁中字符 offset、layout hash 或假設相同換行。
5. 簡中草稿在既有編輯器獨立校對、編輯、確認、發布；不要求先存在簡中 PDF。繁中與簡中發布互不阻擋。
6. 繁中後續變更時提示簡中來源落後；重新轉換產生 incoming 候選，以「上次轉換基底／簡中人工版本／新轉換版本」比對。未經選擇不得覆蓋人工修改或已發布 revision。

## 資料與 API 約束

- 簡中使用獨立 document identity、contentLocale=zh-Hans；issue、日期、期數仍由既有權威紀錄供給，標題/副標保留語言版本的來源關聯。
- 儲存衍生來源 document/revision、來源內容與 metadata 版本、轉換器與設定版本；來源 PDF 仍標為繁中，不建立假的簡中 asset/grant。
- 同來源重複點擊須冪等；使用既有版本比對/CAS，失敗保留舊草稿及已發布版本。背景轉換不能繞过審核或直接發布。
- 同一句在兩種語言可保留結構對應，但私人筆記、標註、進度與離線 receipt 仍依各自 document 隔離；不自動跨語言同步私人資料。
- 既有 exact-edition entitlement 繼續適用簡中，不能因有繁中權限就額外授予簡中。下載照既定授權與 fallback；簡中線上可用不等於有簡中 PDF。
- 會員 payload 不洩漏來源 asset、服務授權資訊或 Admin 衍生欄位。
- 所有新 API 與模型同時更新 hhc-web-api canonical OpenAPI、contract tests 與 frontend-platform generated client。確認 gateway 現有路由政策是否涵蓋新動作，不另建服務。

## Repo 責任

- hhc-web-api：衍生紀錄、轉換工作、資料/權限驗證、metadata、版本比較、排版與發布；migration 必須相容既有繁中。
- frontend-platform：契約 client、簡中字型覆蓋/renderer 支援；不可靜默修改已發布 immutable renderer。
- admin-fe：語言入口、產生/更新簡中草稿、來源落後提示、校對与比對；既有 PDF 上傳不改。
- hhc-web：簡中 online-only、繁中 fallback、語言獨立進度/筆記/離線驗證；不在瀏覽器臨時轉字。

## Admin 顧問發現（唯讀原始碼，非瀏覽器驗收）

### 先處理的資料安全項目

1. 衝突比對 refresh 期間仍可編輯，可能以舊 closure 覆蓋新輸入；先鎖定操作或保留最新編輯快照。
2. 三方比對選擇與手動文字未納入 dirty/recovery；需離頁與重載保護。
3. 顯示歷史版本時仍能確認現行 revision；確認前必須返回現行草稿預覽。
4. 刪除非空段落/項目需確認或一次復原，避免結構誤刪。

### 校對可用性項目

- 分清載入、未儲存、儲存中、排版驗證中/失敗、已儲存；歷史 modal 內就地顯示錯誤。
- 已知校對代碼改成可理解的原因與下一步；數值超限提供欄位提示，不靜默 clamp。
- 選取 component 定位對應預覽頁，長表單保留樹/預覽可用性。
- 字型角色、拆合句與區段操作收進進階；日常改字優先。
- 內容暫覽與已驗證分頁明確區別；新增/刪除/跳轉有合理鍵盤焦點。
- 發布 mapping 失敗定位第一個待處理項目，不能只顯示全域錯誤。

## 驗收順序

1. 繁中真實整鏈：上傳 → 掃描就緒 → 擷取 → 人工改字 → 排版 → 校對 → 獨立發布 → 會員閱讀；重傳差異保護。
2. 繁轉簡：涵蓋人名、經文、繁簡一對多、跨 span 詞彙、標題及固定文案；缺字、斷行、搜尋 offset 與範圍標註。
3. 併發/重試、來源改版、保留人工簡中修訂、語言授權拒絕、online-only 入口、離線帳號隔離。
4. 各 repo 全測試/建置/契約與 migration 驗證；桌機/手機 UI 檢查。實體 iOS/Android/PWA 另列驗收狀態。
5. 提交 merge 前證據清單，不自行 merge、部署或宣稱上線。
