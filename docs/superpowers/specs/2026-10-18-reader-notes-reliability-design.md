# 線上週報筆記可靠性與確認互動規格

日期：2026-10-18。文件版本：S4。狀態：Codex／Gemini 檢驗與修訂處理完成，可進入 plan；本文件不代表實作或裝置驗收完成。審閱紀錄見 [gate record](../../reviews/2026-10-18-reader-notes-reliability-gates.md)。

## 1. 目的與邊界

讓讀者一次操作即可可靠地要求儲存／刪除，知道資料目前在哪裡，並在關閉、衝突與重試時保護草稿。

本次為第一批：筆記新增／編輯／刪除與背景進度協調、結果不明的復原、同步回饋、網站確認框、合併草稿保護、個人狀態／離線初始化失敗的局部提示及重試。畫線／重連也是同一 mutation 入口的相容性範圍，須避免被此次協調改壞。

只修改 hhc-web 閱讀器；預設不改 API、SDK、資料庫、共用 UI package、發布內容、PDF、轉換器或授權模型。不新增依賴或第二套離線 queue。

後續批次另行規格化：紙本／易讀版切換、筆記／畫線搜尋與篩選、側欄分區、搜尋章節脈絡、焦點／瀏覽器縮放改善、筆記匯出、命名書籤。本 spec 不把這些視為本次交付，也不改現有桌面／平板版型或手機換章方式。

## 3. 不可破壞的資料契約

- 操作綁定帳號、issue／series／contentLocale、documentId、documentRevision；延遲操作送出前再次檢查相同綁定與 allowAction。離線操作另檢查既有 owner epoch。
- mutationId、createdAt、payload、baseVersion 一旦可能送達伺服器即凍結；結果不明時只重試原 envelope，不能用新 ID 或不同文字冒充重試。
- 保留 CAS／note_conflict、revision_changed、既有登入／撤銷／到期處理及私人 no-store 邊界。不得為繼續儲存而解除 paused 或跳過驗證。
- 不跨文件／帳號自動搬移草稿；帳號切換、登出、撤銷仍遵循現有清除／鎖定政策。一般網路錯誤不得當成撤銷而清資料。
- optimistic 畫面更新不是持久保存證據。只有 IndexedDB transaction 成功才可說已存此裝置；只有伺服器確認才可說已同步。

## 4. 單次操作與寫入順序

### R1 一次儲存／刪除

符合文字長度、非空、可用授權與版本等既有條件時，第一次完整按鈕啟動即接收一個操作意圖。背景進度正在傳送不能只丟 generic error 並要求再按一次。

- 保持一次一個實際 mutation 傳送。最多保留一個等待中的使用者操作及一個「最新、尚未傳送」進度；不建立無界記憶體 queue。
- 只有未送出的進度可合併為最新位置。已送出或結果不明的進度不可丟棄／改 ID；先確認或原 ID 重試，再處理使用者操作。
- 使用者操作優先於尚未送出的進度；操作等待／執行時立即顯示「等待同步」／「儲存中」／「刪除中」，同一操作重複點擊只送一次。不能只因背景進度 busy 而要求第一次點擊無效。
- 接收意圖時保存文字、noteId、baseVersion、選取 ranges 與完整綁定的快照。延遲 callback 不得讀到後來的 selection／另一筆筆記。等待及執行中的 editor 暫停編輯，避免把已變更文字當成已儲存；失敗／取消等待後恢復編輯且保留文字。
- 從接收使用者意圖算起，20 秒是 UI 連續等待上限，涵蓋 Web Lock、IDB 與整段 sync，不把每個 renew／privateState／mutate 的 20 秒重新累加成畫面無限等待。既有單次 API deadline 仍保留。
- UI 逾時時，先取消尚未送出的續送意圖並恢復保留草稿的編輯狀態，晚到完成不得自動送出該舊意圖。對支援 signal 的等待發出取消；若已在 IDB transaction／同步中，實際互斥直到原工作結束才釋放，不能因 UI 逾時再啟動並行 retry。期間清楚顯示仍在確認，允許保留／離開草稿；後續 Save 可告知仍在處理，但不能假裝建立另一筆傳送。
- 已持久入列的 mutation 即使畫面停止等待仍留在既有 replica；顯示已存本機及待同步／需處理狀態，不能當成未保存清掉。未持久化、可能送達的操作保留原 pending；原實際工作結束後才開放相同 ID 重試，不要求先知道伺服器結果。局部等待失敗不傳成會被誤判為授權撤銷的一般錯誤。
- payload／CAS 快照固定；每次真正開始操作時，optimistic、rollback、replica seed 必須以同綁定最新權威 state/status/value 為基底，不得沿用等待前的 React closure。以 request generation／等效 fencing 阻止舊載入、舊操作或取消後 callback 覆寫較新結果。即使前一筆完成到下一筆開始之間尚未 rerender，也必須保留前一筆結果。
- 背景進度不得搶占筆記操作、覆寫較新的私人 state，或讓使用者成功保存後又因舊回應看見舊資料。

### R2 結果不明與重試

前一操作已可能送達但沒有可驗證回應時，面板內說明「上一筆操作尚待確認」，並提供原操作重試。若原本是背景進度，不能只顯示「筆記儲存失敗」。

- 不做無限自動重試。使用者明確按重試，沿用既有 reader deadline 與原 envelope。
- 後續尚未送出的筆記意圖保留在本次面板記憶體中；原操作確認後，只有綁定仍相同、面板與該意圖仍有效時才續送一次。畫面必須說明這個重試成功後會繼續原儲存／刪除。
- 使用者可取消尚未送出的意圖並回到保留草稿的編輯狀態；這不會取消／清除可能已送達的 pending。若編輯內容改變，不再自動續送舊快照，需重新明確儲存。
- 若 pending 是更早的筆記、畫線或重連，先處理該操作的確認／衝突；不可自動替換成最新筆記。版本變動進入既有 recovery，不盲目重送舊版。
- 網路恢復、快速連點、晚到回應及重驗證重疊，均不得產生重複筆記或跨綁定回寫。
- retry 與 ReaderRecovery 的結算沿用相同結果處理：create/edit、delete、reanchor 各自處理 applied、queued、note_conflict、revision_changed，不能只處理 applied 或把刪除／重連衝突送進無關 editor。舊操作結算僅可清除該操作綁定且未被修改的 draft；不可清除較新的 editor／等待意圖。return-state action patch 須保留同綁定 draft，清除時亦按操作身分判斷。

## 5. 狀態與復原位置

### R3 可理解的保存結果

| 狀態 | 顯示與操作 |
| --- | --- |
| 個人資料載入中 | 明示載入；正文依現有權限可讀，筆記／畫線不接受寫入 |
| 正在等待／傳送 | 宣告目前動作、阻止重複啟動，不能說已保存 |
| applied | 提示已同步；更新列表／關閉 editor，恢復合理焦點 |
| queued 且無已知衝突 | 提示「已存此裝置，待同步」；可結束 editor，不宣稱雲端完成 |
| 已知衝突／revision_changed | 「需要處理同步」優先於 queued 成功提示；面板內可直接開啟既有 recovery，保留本地內容 |
| 結果不明 | 顯示待確認與原操作重試；不把 optimistic 狀態當成功 |
| 個人資料載入失敗且沒有 replica | 顯示「筆記暫時無法載入」及局部重試，不只留 disabled 圖示 |

複用 SyncStatus 及既有 recovery。筆記面板與閱讀器可見位置呈現一致狀態；面板開啟時不必關閉它才能找到重試。需要開 recovery Drawer 時，使用單一可互動頂層面板並保留 editor 狀態；不可把按鈕放在 inert 背景，或堆疊互相搶焦點的抽屜。

本地 mutate 完成結果必須可區分「純入列」與「已知 note_conflict／revision_changed」，包含線上同步離線 replica 的分支；不能將已知衝突壓成無資訊的 queued。這是 hhc-web 內部回傳契約，不改 SDK/API。已知衝突保留當前草稿與可達的復原畫面，不走一般成功 cleanup。

queued delete 可沿用既有 optimistic 隱藏，但須留下可見的待同步刪除狀態／復原入口；遇衝突必須再次顯示可辨識的衝突項目。刪除失敗不假裝成功，不自動重建已刪除筆記，不新增 Undo 契約。

### R4 局部載入失敗

privateState 初取重試只重載同一綁定的個人狀態，不重新整理整個頁面或丟掉草稿；若必須重新驗證，沿用現有安全遮罩且取消過期 callback。重試載入不能覆寫未確認／已入列的操作。

OfflineControl 必須區分不支援、載入中、初始化錯誤、可儲存與已儲存。初始化錯誤顯示小型提示及重試；不支援則可隱藏控制項，不假設具有離線保存能力。讀取／寫入失敗都不顯示保存成功。

## 6. 確認框與草稿

### R5 統一網站確認

閱讀器內的取消編輯、X／Escape／遮罩關閉、切換週報、切換會關閉草稿的面板，以及一般刪除／刪除衝突後再次刪除，統一使用既有 AlertDialog；這些路徑不再呼叫 window.confirm。本次未涉及的畫線歷史清除、部分色彩復原與離線清單刪除確認另列後續一致性工作，不宣稱整個 reader 已移除原生確認。

- dirty 草稿：提供「繼續編輯／放棄變更」；未變更直接關閉。刪除：指明將刪除筆記並提供取消／刪除，使用危險操作樣式。
- 取消不得清理草稿、選取、閱讀位置或 pending；只在確認後執行對應動作一次。重複 Escape、點遮罩、連續返回不建立多個確認或重複操作。
- 已有 Home／瀏覽器返回的 ReaderExitDialog 繼續合併未存警告，只出現一框；取消保留狀態，確認後沿用既有有界進度 flush。不得額外再問一次放棄。
- 網站 Dialog 支援鍵盤、焦點圈限、合理初始焦點與取消後回到原按鈕／editor；light/dark、safe area、44px 觸控目標、五種 UI 語言沿用現有元件規範。
- 重新整理、關閉瀏覽器分頁、程序被系統終止不承諾顯示網站 Dialog；不為此新增不可保證的 beforeunload 流程。現有 sessionStorage 草稿只是有期限的復原，不是雲端保存。
- 已送出的操作不能靠關閉／放棄草稿「取消」。等待中的未送意圖可取消；已送出或 ack 不明的 mutation 仍保留既有確認／復原資料。離開閱讀器不得清掉這些操作。
- 只有背景進度在途時不能封鎖筆記面板關閉。等待未送出時，經 dirty 確認後取消該等待意圖；已送出筆記操作時暫停面板 X／Escape／遮罩關閉，直到完成或 R1 的 UI 上限，並明示原因。Home／瀏覽器返回仍依既有單一確認與有界離開，不因筆記鎖住整站；卸載 abort 亦須保留可能送達操作的原 pending，不因略過 catch 而丟掉確認資訊。
- 編輯衝突的「採用雲端」是明確捨棄本地版本的決策，不再呼叫一般取消而二次詢問。雲端已刪除時不提供會抹掉 noteId/baseVersion 的本地覆蓋／手動合併快捷徑；保留本地文字供既有人工 recovery，不靜默由 editNote 轉 createNote。

### R6 手動合併與原始版本

刪除版本衝突後的「手動合併」必須保留雲端原 note 作為 baseline，以雲端最新 id／baseVersion 建立明確 dirty draft，文字為雲端與本地合併值。未再打任何字便關閉／切換／離開，也必須提醒；取消確認保留完整文字。儲存走 editNote CAS，不能把合併文字寫回 baseline 讓 dirty 判斷失效。

沿用現有同帳號、文件與 30 分鐘期限的 return-state 復原，明確將合併 draft 寫入既有流程；儲存空間被禁用時保留當前 editor 並不可宣稱可復原。雲端已刪除或版本不符時走既有保留／人工 recovery，不自動以新 note 取代。

## 7. 驗收矩陣

| ID | 情境 | 通過條件 |
| --- | --- | --- |
| A1 | 延遲背景 progress，首次 Save／Delete | 一次啟動被接收，顯示等待，背景確認後只送一次且結果正確；不經 rerender 續送也使用最新 state，第二筆失敗不回滾掉第一筆結果 |
| A2 | progress timeout／lost ack，再 Save | 面板內可重試原 ID；20 秒內確認後有效意圖續送一次；逾時或取消等待留草稿，晚到完成不續送；實際工作未結束時不並行 retry |
| A3 | createNote／editNote 回應遺失後重試 | 原完整 envelope 不變；伺服器僅一筆結果，不重複建立或覆寫他人修改 |
| A4 | 一般刪除、CAS 衝突、queued delete | 各自呈現成功／衝突／待同步；不把 queued 說成雲端已刪除 |
| A5 | 手動合併後未編輯就關閉／切換／離開 | 有且僅一個網站確認；取消保留完整合併；有效期內重整可還原 draft |
| A6 | X、Escape、遮罩、Home、返回、週報 tab | dirty 保護一致，本次筆記／離開路徑無 window.confirm；取消不清資料，確認不重複導航 |
| A7 | 離線新增／編輯／刪除後恢復網路 | 本機 transaction 成功才顯示已存本機；等待→同步／衝突可見，無第二份 queue；Web Lock 長占用、多筆 sync 超過 20 秒仍有可理解的 UI 結束與持久資料 |
| A8 | privateState 503、IDB 初始化 reject、quota | 正文依權限可讀；有局部說明／重試；無假成功或草稿遺失 |
| A9 | 等待／重試時切帳號、revision、登出、到期 | 不送舊意圖、不接受晚到回應；保留或清除資料依既有安全政策 |
| A10 | 背景進度與畫線／reanchor、快速連點 | 共用入口仍序列化，原 ranges／Unicode scalar／CAS 不變 |
| A11 | iPhone Safari／PWA、Android Chrome | 中文組字、鍵盤開關、長筆記、旋轉後完整點擊一次即接收；儲存／取消可達 |
| A12 | iPad Safari／分割畫面、桌面鍵盤 | Dialog／Drawer 焦點、狀態宣告與觸控目標正確，既有閱讀版型不變 |

A2–A5 另須覆蓋重試回 queued、delete/reanchor 衝突、舊結算不清新草稿、雲端已刪除的編輯衝突及採用雲端不二次確認。A6/A9 須覆蓋在途卸載仍保留原 envelope。

A1–A10 須有可重現的合成資料整合／單元測試；A11–A12 為實體裝置驗收，桌面模擬不能替代。若 A11 的 first tap 問題仍在，先記錄不含個資的 pointer／blur／composition／submit／驗證事件序列，取得根因後再修，不先攔截 touchstart 或固定延遲。

## 8. 視覺品質與操作密度（V1–V5）

- **V1 保留視覺基準：** 正文、字型、字級、行距、配色、閱讀寬度、工具列位置與桌面／平板紙張樣式維持既有設計。只在原筆記面板／動作附近補必要狀態與同系統確認框，不新增常駐頂部橫幅或重新排版閱讀內容。
- **V2 漸進回饋：** 一般成功以單一位置短暫提示，不移動焦點、不累積 toast；等待／處理中顯示於原動作區。只有未同步／結果不明／需處理衝突保留可操作提示。同一面板同時最多一個主要狀態訊息；不同訊息依錯誤／衝突→結果不明→進行中→一般成功排序。閱讀器外部狀態不能與面板內重複宣告。
- **V3 前後同條件比較：** 用相同合成文件、閱讀位置、內容與字型載入狀態，保存 baseline／candidate 截圖及量測。桌面1440×900、平板768×1024、手機390×844，均含light/dark；比較正常閱讀、筆記列表、長文編輯、dirty確認、刪除確認、等待／錯誤／衝突。正文／工具列邊界與換行不應因本次狀態UI改變，正常閱讀無新增佔位或水平溢出；字型與抗鋸齒差異不以全圖pixel完全相等判定。
- **V4 視覺審查是門檻：** 兩席顧問須實際取得合成畫面的baseline/candidate並評估密度、間距、層級、對比、截斷與狀態佔位，不能只讀程式碼代替。Codex使用圖片檢視；Gemini只能透過官方CLI支援的圖片輸入接收本次合成截圖，不傳正式私人畫面。若圖片輸入或截圖不可用，記錄阻塞，不宣稱視覺通過，也不merge。其他可獨立完成的實作及CI仍繼續。
- **V5 裝置限制：** 模擬viewport／鍵盤高度可檢查排版，不代替實體iOS鍵盤、組字與PWA生命週期。未取得真機證據明列未驗收；不以修改viewport充當真機接受。只有補完本機／CI及視覺門檻後可將PR標示ready，merge仍須使用者核准。

## 9. 交付與交付授權

先完成 spec 的 Codex＋Gemini 獨立檢驗、處理阻塞發現，再建立 implementation plan；plan 同樣經兩席檢驗後停止。文件審閱通過只表示可供實作決策，不是實作、CI、合併、發布或真機接受。

後續實作若需改 producer contract／共用 UI 才能滿足規格，先更新 spec／plan 並列出跨 repo 順序，不能在 hhc-web 複製另一套服務能力。2026-10-18 使用者追加授權：補齊視覺門檻且雙席檢驗後開始實作，各步雙席檢驗（Codex＋Gemini），最後開 PR／完成 CI 並停在 merge 前。不 merge／release，不操作既有正式筆記。
