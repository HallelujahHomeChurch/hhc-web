# T0 — baseline and feasibility

Base: origin/main d2d5ff6. Isolated implementation branch; no production data or services.

## Storage decision

Extend the existing IDB private replica/queue, not a second queue. Persist online-only access binding in `checks` (marker, account/document/revision/edition/epoch/deadline), while keeping canonical document in a bounded runtime registry populated only by fresh validated online access. Do not put a document in `documents`, create an OfflineSave or download assets. Existing offline reads must still return unavailable for online-only bindings. All private transactions continue checking active identity/epoch/deadline. A cold tab cannot access/replay an online journal until fresh authorization installs its runtime binding. Explicit logout/revocation purges or locks it through existing cleanup paths. Pending data must survive ordinary removal/refresh.

Enqueue runs separately from the single network writer; existing atomic ack replays later queue entries. Use projected local versions for subsequent same-note CAS and freeze sent IDs/payloads. IDB denied/quota falls back to retained in-memory intent with persistent not-saved/retry UI, never a fake durable status. Test pending/expiry/revision/cross-tab as well as no-offline-save paths before proceeding.

## Binding and lifecycle compatibility contract

| Path | Online-only behavior to implement in T1 | Existing capability retained |
| --- | --- | --- |
| Cold open | Fresh `open`/`renew` must succeed before registering the runtime document. Bind `checks` and edition pointer atomically to account/document/revision/epoch, a random journal instance ID, receipt/window and `onlineOnly:true`. Preserve same-binding queued mutations when receipts refresh. Never create `documents` rows. | `private` holds the same confirmed/state/queue shape. |
| `privateContext` | Explicitly distinguish saved document and online-only metadata. For online-only, require exact runtime selector/document/revision/epoch, access window and unlocked check before returning the runtime document. Missing registration fails closed. Use a context type, not a fake OfflineSave. | Account/epoch, canonical validation, rollback clock and IDB transaction enforcement. |
| Refresh and ack | Enqueue locally without holding network lock; ack reads the latest queue in the same transaction, projects remaining entries with the runtime canonical document. Sent payloads/IDs freeze; subsequent same-note versions derive from prior projected local state. | Single account network writer, CAS, ordered queue. |
| Export | Extend snapshot readback to journal instance ID + owner/epoch + exact binding/access/replica fingerprint. Require fresh runtime context; same invalid sent/result/recovery fields still reject. Recheck before download. | Unsent durable projection validation; complete vs filtered snapshot. |
| Revision/recovery | Same revision refresh preserves queue. Revision change pauses; keep prior journal and intents locked. Recovery reads retained journal intents with explicit fresh ownership; rebase against fresh in-memory canonical document through existing recovery transaction. Online-only recovery must update binding/replica without `stageOfflineSave`/asset download; split that branch from explicit offline upgrade. Missing old document must expose manual local/cloud recovery, never guess anchors. | Existing recovery schema, explicit user decisions, CAS/queue snapshot checks. |
| Normal offline removal | Inspect pending journal + draft before removal. Block stale snapshots and ordinary removal while a journal still has unconfirmed operations. Require sync/recovery or an explicit, clearly scoped discard decision before removing those intents; cancellation keeps the journal. If assets alone are removed while intents are retained, keep minimal online-only metadata and require fresh online registration. Never silently delete pending journal with a downloaded document. | Removal fingerprint and user-facing pending consequences. |
| Owner denial / revocation | Separate destructive security purge from normal removal. Purge same-owner documents/checks/private/pointers and clear runtime registration; lock denial immediately gates access/replay. | No pending-data exception to revoked authorization. |
| Logout / account switch | Purge runtime registrations and persisted account rows; epoch invalidates all in-flight work. Normal logout warns for pending work; forced logout never delays isolation. | Existing identity transaction and cross-tab notification. |
| Offline content listing | Online-only binding is never listed or returned as OfflineSave; no resources/byte size/content retained. | Existing saved-document listing checks `documents`. |

T1 touchpoints: offline-store privateContext, binding/removal/export/recovery transaction functions; sync fresh binding; hook enqueue/writer separation; recovery offline-vs-online branch and removal snapshot guard. Tests must include cold unregistered reads, refresh/remount, expiry/clock rollback, owner/epoch change, no OfflineSave creation, late ack plus later edit, and journal export/removal/recovery. These are implementation obligations, not claimed passing paths.

## Regression evidence

Two `it.fails` cases capture the current defects: background focus validation blocks still-valid actions; a refreshed receipt for the same binding cancels an accepted mutation. T1 must turn both into ordinary passing tests. Expected failures are temporary baseline evidence, not product acceptance.

## Selection and document feasibility

Paper and ebook expose canonical sentence ID and scalar fragment start/end. Reuse DOM Range geometry, validate fragment text against canonical scalar text, then split only Chinese comma/period with closing punctuation. Reject unresolved hit tests; never guess another fragment. Desktop native selection stays intact. Selection rendering must use precise ranges rather than whole-sentence `selected`.

Use the browser-compatible `docx` builder (https://docx.js.org/api/classes/index.Packer.html) for OOXML serialization and packaging, loaded only on export. T5 must inspect the actual XML size in addition to input and ZIP limits, and render the actual product-generated artifact. Export snapshot/owner checks remain in use. No hand-built ZIP format, HTML masquerading as Word, or cloud document integration.

## Visual direction

Preserve existing HHC surface, typography, palette and focus tokens. The signature is a consistent quiet reader workspace: fixed 64px title/X header, common bottom-sheet silhouette and opaque fullscreen search. 44px targets, balanced centered tabs, compact icon actions and calm state feedback. `proposal.css` demonstrates layout on the actual mounted reader components only; shared production shell is implemented in T2, not inferred from this prototype. Motion values and complete acceptance matrix are in the plan sections 6/10.

## Reproduce

Run `node docs/reviews/reader-professional-20261019/preview.mjs "$PWD"`; it is loopback-only and synthetic. `?prototype` loads only the T0 component proposal, while the default route loads unchanged WeeklyReader. The capture scripts document the current browser task ID and absolute evidence location; later runs must use their own TaskSpace/page/path.

For Word render, use the installed Codex primary runtime Node/Python/LibreOffice dependencies described by its runtime.json. A task-local FONTCONFIG_FILE must include `/System/Library/Fonts`, its Supplemental folder and the current AssetsV2 CJK font folder; do not change global font settings or substitute the user's desktop LibreOffice.

`verify-t0.py` passes PNG dimensions, shared geometry, search focus, DOCX content/size/external-link checks and artifact presence. Video containers were separately checked with ffprobe (approximately 4s prototype / 3.20s baseline), while their original captured frame sets remain available.
