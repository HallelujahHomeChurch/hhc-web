# T5 — readable Word export

Candidate scope: replace Markdown with real `.docx` using the already pinned `docx@9.12.0`, loaded only when preparing an export. No API/SDK contract or cloud-document service was added.

## Behavior and safety

Every entry contains only its saved `note.quote` and own `note.text`, in list/snapshot order. Localized Quotation/My note labels separate a gray indented quote and normal body. Preserve Unicode, paragraphs and blank lines. Do not derive quotes from current canonical text, ranges or inactive anchors. A missing saved quote exports only own text; its count stays in the export UI. No bulletin title/full text, source metadata, timestamps, IDs, URLs, sync annotations or Markdown wrappers are added to the Word body. User-authored literal URLs/Markdown remain ordinary text. Labels keep with their next paragraph; content can flow across pages; no cover, page header/footer, or decorative rules.

The original private snapshot/owner/epoch/revision/fingerprint and final download validation remain in use. Export does not trigger synchronization. After asynchronous builder completion, recheck live component/qualification before creating a URL; late closed/revoked requests publish nothing. A ref prevents duplicate preparation/download work. Keep actual gesture checks, explicit prepare/download steps and delayed object-URL cleanup. A single polite status combines readiness/local-state and missing-quote information; preparing feedback stays inside the dialog. Over 200 notes now returns the specific limit message, while a smaller explicit filter remains available.

Validate text/scalar count, XML 1.0 characters and well-formed Unicode. Entire export rejects above 200 notes or 8 MiB raw UTF-8 input. Preflight mandatory escaping and minimum paragraph markup to reject oversized/newline-heavy input before building millions of objects. After the public Packer generates the archive, inspect its ZIP directory's total uncompressed size (all parts, stricter than XML alone) and final ZIP bytes against 8 MiB. The ZIP reader only measures the trusted builder's output; it does not build ZIP/XML or use private docx compiler APIs. Serialization/packaging remains the public builder. Blank author/title/description metadata; no macros or external relationships.
