# T1 — Reader persistence and quiet background work

## Scope

T1 implements the storage/interaction contract from the approved plan. T2–T6 UI layout, motion, mobile clauses and product Word export remain separate gates. No merge, deployment, production data or real account was used.

- Same account/document/revision receipt refresh keeps the private reader owner and pending requests. A still-valid access window permits actions during background revalidation; clock rollback, expiry and known denials still block.
- Notes/highlights apply through the existing private replica and immutable mutation queue. Local acceptance closes the editor to the list or clears the acted selection immediately. Later network results cannot close a newer editor/selection. Delete conflicts retain explicit cloud/local resolution.
- Online-only users use the same IDB stores/queue with minimal access/hash/instance metadata. Canonical documents are runtime-only; no `documents` row, resource download or OfflineSave is manufactured. A cold tab requires fresh registration. An old revision with pending intents remains recovery-only until an explicit queue-checked commit.
- Local enqueues do not wait for the network writer. Atomic acknowledgement replays newer queued edits over confirmed state, retaining IDs, text and CAS. Account network synchronization retains its existing single-writer lock.
- IDB denial/quota uses the same replica shape in memory. Unknown IDs remain retryable; reconnect resumes durable entries. A known epoch is checked before every memory resend. Storage fallback cannot bypass an owner change or a non-storage denial. Memory-only/uncommitted work warns on browser termination and does not claim durable save or export eligibility.
- Ordinary background qualification/loading and per-save success messages no longer appear beneath the reader header. Normal sync state is confined to the notes panel. First-load skeletons, persistent recovery errors, authorization failures and conflicts remain visible.

## Evidence

`T1-save-transcript.json` and `T1-save-{pending,settled}.png` are actual Ego Chromium runs of the product `WeeklyReader`, using a synthetic account/API with a 3,500 ms delay per mutation. Two semantic edit/fill/Save sequences, with a window focus refresh between them, both returned immediately to the list. Both snapshots were taken while the synthetic server still held version 1. Exactly two distinct edit mutations used CAS 1 and 2; final visible/server content matched the second edit at version 3. Neither snapshot had a loading overlay. Root inspected both images and asserted these transcript invariants.

The existing mobile panel still changes height and still includes the old history tab in these images: those changes intentionally belong to T2. These are T1 interaction evidence, not final UI acceptance, latency benchmarking or iOS device evidence.

## Validation ledger

- Storage, sync, upgrade, session, bookmarks, export and Recovery checks: 128 passing tests across 11 files (bounded worker run; full commands match the named files in the source tree).
- Latest hook checks (`usePrivateReader.test.tsx`, `usePrivateReader.online.test.tsx`): 18 passing tests, including IDB quota, durable reconnect, cold mount, continuous edits, delayed acknowledgements, unknown IDs and account/epoch isolation.
- Integrated `WeeklyReader.test.tsx`: 130 passing tests, including first Save with and without a focus refresh, immediate toolbar dismissal, dirty-draft protection and delete-conflict recovery.
- TypeScript, affected-source/tests ESLint and `git diff --check`: PASS. Total targeted scope: 276 passing tests in the successful grouped runs; these are not a claim of full repository CI.
- Early candidates were not green: a broad run had timeout/readiness failures; a later candidate exposed the missing epoch check in the memory resend path. A globally added Range geometry stub also interfered with mobile source-page hit testing; it was restricted to the two highlight-overlay cases that need it. These failures were fixed before this gate and are not counted as passes.

## Remaining acceptance

Real iPhone Safari/PWA, Android IME, process termination under device storage pressure, real account/session recovery, and final release smoke remain unverified. Per the plan, they must stay distinct from synthetic browser/unit evidence. Full repository CI/build and final integration remain T6. The work stops before merge.
